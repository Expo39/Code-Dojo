# Discussion questions: m02_prompts_structured_output

Questions for a discussion drill: answer out loud, at your level, with a concrete
example; the tutor follows up (why? when would you not?) and judges against the read-first sources (track
README). No answers here on purpose.

1. How do you structure a prompt so that the instructions, the data and the expected format cannot be confused?
2. When do few-shot examples help, and when is a clearer instruction better?
3. Why must you parse and validate a model's JSON instead of trusting it?
4. The model returns almost-valid JSON about 3% of the time. What are your options, in order, and what does each cost?
5. What is a hallucination, and which mitigations actually reduce it? Which only look like they do?
6. How would you design a prompt for extracting invoice fields, and how would you know it works?
7. What is the difference between asking for JSON in the prompt and using a provider's structured-output or tool-calling feature?
8. What does chain-of-thought prompting or a reasoning model add, what does it cost, and when would you not use it?
9. Name two uses of image or audio input in a product and the failure you would test for in each.
