# Glossary

The words the dojo uses, in plain language. The tutor explains any of them when they come up;
this page is for looking one up on your own.

## How you practise

| Word | Meaning |
| --- | --- |
| **Exercise** | A small task with a starter file (the *stub*), tests that check your answer, and a target time. You write the solution in your own file under `workspace/`. |
| **Stub** | The starter file: the task description and an empty function for you to fill in. |
| **Test** | A small program that runs your code on chosen inputs and checks the answers. "Pass" means every check gave the right answer. |
| **Target time** | How long the exercise should take someone at that level working alone. Your time is compared with it (for example 1.2x = 20% longer). |
| **Hint level** | Help comes in 5 steps, from a single question (1) to a full explanation of a solution (5). The tutor always starts at the lowest level that could help. |
| **Redo queue** | Exercises that come back after some days, to be solved again from an empty file. Solving from memory is what makes skills stick. |
| **Box** | Where an exercise sits in the redo queue. A clean solve moves it up a box (it comes back later); a struggle moves it to box 0 (it comes back tomorrow). Box 4 or higher counts as mastered. |
| **Clean solve** | Solved with no hints, at or under the target time. |
| **Clarify** | Asking about details the task leaves out (empty input, ties). In the dojo, `clarify <exercise>` gives the answers an interviewer would give. |
| **Trace** | Following code by hand, line by line, writing down the value of each variable. |
| **Edge case** | An unusual input that often breaks code: empty, one item, duplicates, negative numbers. |
| **Complexity (Big-O)** | How the time or memory a program needs grows as its input grows. O(n) grows in step with the input; O(1) stays the same. |

## How you learn

| Word | Meaning |
| --- | --- |
| **PRIMM** | The way new ideas are taught: **P**redict what some code does, **R**un it, **I**nvestigate why, **M**odify it, then **M**ake something of your own. |
| **Theory lesson** | A short lesson on background a topic needs (for example Big-O before hash maps), offered just before you need it. |
| **Drill** | A short practice of one skill: predicting output, tracing, finding a bug, reviewing code, explaining. |
| **Mock interview** | A practice interview: an unseen problem, a timer, the tutor acting as the interviewer, then scored feedback. |
| **Strand** | One kind of practice: learn, write, read and debug, build, perform. Your week mixes them (`METHOD.md`). |
| **Cheat sheet** | Your own short notes, one line per concept with a self-check question (`progress/cheatsheet.md`). |

## How the plan works

| Word | Meaning |
| --- | --- |
| **Track** | A subject, such as Python or C++. Each track has modules. |
| **Module** | A topic within a track, such as "dicts and sets", with its exercises. `python dojo.py modules` shows yours: *assigned* (offered as new material), *excluded* (left out; its redos still come back), *planned* (no exercises yet). |
| **Mode** | Why you train: `interview`, `hybrid` (interview plus growth), `industry` (entering a field) or `hobby`. It sets how much interview practice you get. |
| **Target level** | The programmer you want to become: hobbyist, junior, mid or senior. It sets how far each goal goes. |
| **Bar** | How far is enough for a goal, in your own words. Training stops at the bar, then the track goes to maintenance. |
| **Milestone, gate** | A measured checkpoint (for example "last 10 easy exercises at or under target with no hints"). A gate is the test that says a milestone is met. |
| **Roadmap** | Which tracks you follow, in what order, and why (`progress/PLAN.md`). |
| **Skill tree, rings** | Your roadmap drawn as rings: the inner ring first; an outer ring opens when the inner one's gate is met. |
| **Mix** | How new-material time is split between tracks (for example Python 80%, C++ 20%). |
| **Taster** | A new track started small (10 to 20% of the time) next to your main one. |
| **Maintenance** | A track gets no new material, only its redos, so you keep what you learnt. |
| **Settings** | Your profile: mode, target level, hours per day, tracks and more. `python dojo.py settings` shows them; the weekly review suggests changes for you to accept or decline. |
| **Track changes** | New, changed or removed exercises and lesson topics in your tracks since you were last asked (also in modules you already finished), for example after `update`. Each session start lists them and asks what you want: learn it or redo the new version, already know it, or not for me; removals are explained first. |
| **Weekly review** | Once a week: your numbers, what went well, what to fix, next week's focus, and suggested settings changes. |
